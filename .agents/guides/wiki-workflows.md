# Wiki 工作流

所有知识库任务先读 `wiki/index.md`，再读相关页面和原始材料。默认一次只处理一个来源。除“完整质量剔除”外，每个工作流完成时在 `wiki/log.md` 添加 `## [YYYY-MM-DD] <kind> | <title>`；`<kind>` 只能是 `ingest`、`deepen`、`distill`、`verify`、`refactor`、`maintenance`。日志是简短的**当前保留知识**时间线，不记录未完成工程或工具工作实录。

## ingest

当 `raw/` 中有新的 PDF 时：

1. 读原文，识别实体、核心主张、机制、矛盾、核心图表。
2. 创建 `wiki/sources/<slug>.md`；若论文发布了明确的新模型实体，再创建 `wiki/models/<slug>.md`。
3. 更新已有的相关概念页；只有没有合适归宿时才创建新概念页。若属于既有比较，更新对应比较页。
4. 输出图文交错页面：嵌入机制、架构或核心结果图；可搜索的纯文本表格改排为 Markdown 表。除非论文确实没有值得展示的图，否则至少嵌入一图；例外要在日志说明。
5. 更新 `wiki/index.md` 的入口和一行中文摘要，完成链接与证据检查，再追加日志。

图表、证据等级和 VLM 的判断按 `evidence-and-visuals.md` 执行。

## deepen 与 distill

- **`deepen`**：为已有页加深或校准。必须重读相关 `raw/` 一手材料，不得仅凭旧摘要或记忆；只修改问题涉及的页面并补双向链接。
- **`distill`**：把持久、可复用且跨至少两个来源 / 页面的对话洞见写回。已有主题页优先扩展；跨页新框架才新建概念或比较页；未解问题写入相关页 `## 待追问`。单一事实回答不写回。

两者都要按证据与视觉规范重新核验；日志按主动作选择一种 kind。

## verify

重读一手 PDF，必要时以外部独立来源交叉验证。逐条给出 `supported`、`refuted` 或 `not-found-externally-but-confirmed-in-primary-source`；被证实只是推断的陈述必须降级。不要用二手材料升级原文确证。

## refactor 与 maintenance

- **`refactor`**：在不改变事实或引用的前提下重排、去重、删除读者向内部工具痕迹；记录完成动作。
- **`maintenance`**：处理语言统一、schema、链接、版本控制、陈旧主张、矛盾、孤儿页或缺失交叉引用。优先降低检索负债：合并重复表达，不为同一主题拆近亲页；但不为简短而删除机制解释或证据链。

### 完整质量剔除

若 `verify` 重读原文后有具体、可证实的理由判定一项来源低质量或不值得继续保留，执行**完整移除**，而不是留存降级页或“为什么移除”的说明：

1. 删除 `raw/` 原始材料、其来源/模型页、对应图像资产、所有交叉引用与 `wiki/index.md` 条目。
2. 删除该来源原有的 ingest / 后续日志条目；**不**新增剔除日志。Git 历史是唯一审计层。
3. 如果来源只是证据有限、但仍有可复用事实或历史价值，则不触发剔除；诚实降级至对应页面的 `## 待追问` 或限定表述。

这个例外覆盖“正常工作流不修改 `raw/`”和“每个工作流追加日志”两条默认规则。
